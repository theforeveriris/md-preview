## 一、内容与渲染

### 1. 文档演示模式（`?mode=slides`）

> **状态：已否决 ✋**——经评估不提供此功能（入口与整体阅读流冲突），以下保留原方案说明备查。

给任意文档加 `?mode=slides`，按 H2 分页、方向键翻页、全屏放映——写完文档直接拿去讲，让每篇文档一键变幻灯片。

**交互草案**

- URL 参数进入 / 退出，与 `?mode=editor`、`?mode=pulsegen` 的既有惯例一致；
- 以 H2 为分页边界，H3 及以下内容归入所属 H2 的页；文档开头（第一个 H2 之前）单独成页；
- 页脚显示页码与当前章节标题；`←` / `→` / `Space` / `Shift+Space` / `Home` / `End` 翻页，`Esc` 退出并恢复滚动位置。

**复用基建**

- PPTX 全屏放映层 `#pptx-slideshow-overlay`（`iris/js/renderers/pptx.js`）：backdrop + 单页容器 + 键盘事件已在捕获阶段监听并 `stopPropagation()`，优先级高于通用灯箱（见 [开发者文档](../readme-dev.md) 相关小节）；
- `?mode=` 特殊页面路由（编辑器、波形生成器均已使用）；
- i18n 语言包（`iris/js/i18n.js`）承接新界面文案。

**实现要点**

- 分页应基于渲染完成后的 DOM（`.markdown-body` 的 H2 切片），图片 / Mermaid / 表格已经渲染好，无需重跑渲染管线；
- 退出时恢复进入前的滚动位置与 URL；
- 可顺带提供「导出讲义」打印样式。

### 2. CSV / TSV 交互表格

> **状态：已实现 ✅** ```csv / ```tsv 代码块直接渲染为交互表格，示例见 [CSV/TSV 交互表格示例](examples/csv-examples.md)。

` ```csv ` / ` ```tsv ` 代码块渲染为可排序、可筛选、可搜索的交互表格，贴数据的人会常用。这是长表格横向滚动优化的自然延伸。

**交互草案**

- 表头点击排序（升 / 降序切换，箭头指示）；
- 右上角搜索框即时过滤行；每列下拉勾选筛选；
- 行数多时保留横向滚动与「延伸到右侧空白」能力；
- 工具栏提供「复制 CSV」「下载 CSV」。

**复用基建**

- 渲染器注册机制（`iris/js/renderers/`，`detect` + `render` 两段式）；
- 长表格横向滚动与「延伸到右侧空白」设置（`iris/css/markdown.css` + 显示设置）；
- 表格手柄已有的「复制 CSV」逻辑（`iris/js/interactions.js`）。

**实现要点**

- 数据量在内存中，纯 DOM 排序即可，无需引库；
- 建议超过约 5000 行时退化为普通代码块高亮，避免卡顿；
- TSV 按制表符分列，注意引号转义与空行跳过。

### 3. Cisco IOS / 华为 VRP 配置高亮

> **状态：已实现 ✅** ```ios / ```vrp（别名 ```cisco / ```huawei），示例见 [IOS/VRP 配置高亮示例](examples/ios-vrp-examples.md)。

自定义两个 highlight.js 语言包，` ```ios ` / ` ```vrp ` 渲染路由器配置。本站受众本就是网络工程师（PKT / eNSP 拓扑渲染已内置），配置高亮比任何图都戳中痛点。

**交互草案**

- 命令关键字（`interface` / `router ospf` / `acl` / `display current-configuration` 等）、注释（IOS 的 `!`）、字符串与数字分级着色；
- 与内置 10 套代码高亮主题自动兼容（仅依赖 hljs class 体系）。

**复用基建**

**实现要点**

## 二、阅读与导航

### 4. 浏览历史与收藏夹

> **状态：已实现 ✅** 长按文件树文档一键收藏（图标变强调色），最近打开的 5 篇在文件树中淡化显示；未设独立侧边栏分组。

localStorage 记录阅读轨迹，侧边栏新增「最近阅读」「收藏」两个分组。配合已有的本地文件会话列表，整体导航体验就完整了。

**交互草案**

- 每篇文档阅读超过阈值时间（如 5 秒）记入历史：标题 + 路径 + 时间，去重、上限约 50 条；
- 收藏入口（悬浮球菜单或标题旁星标），一键收藏 / 取消；
- 两个分组渲染在侧边栏，与「本地文件」面板同级、可折叠，点击条目走既有 hash 路由；
- 分组标题栏提供清空入口。

**复用基建**

- 侧边栏面板结构（本地文件面板：`iris/js/local-docs.js` + `iris/css/layout.css`）；
- 文件树条目渲染与点击路由（`iris/js/file-tree.js`）；
- i18n 语言包。

**实现要点**

- 数据结构建议 `md-preview-history` / `md-preview-favorites` 两个 localStorage 键；
- 隐私模式下 localStorage 可能抛异常，读写需 try/catch；
- 历史去重以文档路径为键，本地文件与会话文档可不入历史（刷新即失效）。

### 5. 链接悬浮预览

> **状态：已实现 ✅** 悬停站内链接弹出目标文档摘要卡片（标题 + 摘要 + 阅读时长），点击卡片跳转。

鼠标悬停站内链接时，弹出目标文档的摘要卡片（Obsidian / 维基百科同款），不用离开当前页就能确认要不要跳。

**交互草案**

- 悬停约 300ms 后浮出卡片：目标标题 + 首段摘要 + 字数，跟随链接定位；
- 点击卡片跳转，`Esc` 或鼠标移出关闭；触屏设备暂不支持（或长按触发）。

**复用基建**

- hash 路由解析（`iris/app.js`）确定目标文档路径；
- 按路径拉取单篇 `.md` 的运行时请求逻辑；
- frontmatter 解析（`iris/js/markdown.js` 的 `parseFrontmatter`），`description` 字段已用于 OGP meta。

**实现要点**

- 摘要取 `frontmatter.description` > 正文首段（可复用 OGP 的摘要提炼逻辑，剥代码块 / 图片 / 标记语法）；
- 卡片内**不渲染完整 Markdown**（XSS 攻击面收敛），仅纯文本 + 少量受控格式；
- 对已打开过的文档可做内存级缓存，避免悬停风暴重复 fetch。

## 四、离线与 PWA

### 9. 全量离线开关

> **状态：已实现 ✅** 设置面板 → 操作 → 「缓存全部文档」，支持一键清除文档缓存。

PWA 目前只缓存访问过的页面。设置里加一个「缓存全部文档」按钮，一键把 `search-index` 覆盖的所有 `.md` 拉进 SW 缓存，飞机上也能整站阅读。

**交互草案**

- 设置面板新增按钮与进度显示（n / total，可取消）；
- 完成后提示「已可整站离线」，并显示当前缓存文档数与「清除缓存」入口。

**复用基建**

- `sw.js` 的 RUNTIME_CACHE 已按 `.md` 路径后缀拦截并缓存访问过的文档；
- `iris/data/search-index.json` 覆盖全部文档路径，可作清单来源；
- `precache-manifest.json` 的预缓存机制与版本管理。

**实现要点**

- 逐个 fetch `.md`（并发 3~5）触发 SW 拦截入库，避免一次性全量拉爆移动端流量；
- `CACHE_NAME` 版本升级后旧缓存会被清除，需提示用户重跑「缓存全部」；
- 渲染一篇文档还依赖 vendor 库，可顺带把常用 JS/CSS 一并纳入（或依赖 precache 已覆盖）。

### 10. OS 级文件关联

manifest 加 `file_handlers`，安装 PWA 后双击 `.md` 文件直接用本站打开，配合 File System Access API 就是桌面 MD 阅读器。

**交互草案**

- 系统层面把 `.md` / `.markdown` 关联到已安装的 PWA；
- 启动后通过 `launchQueue` 拿到文件句柄，转入本地文件会话打开。

**复用基建**

- `manifest.json`；
- 本地文件管线（`iris/js/local-docs.js`：会话列表、懒加载、大小限制）。

**实现要点**

- `window.launchQueue.setConsumer()` 接收 `FileHandle` → 读 File 后走「打开本地 MD」同一入口；
- 仅 HTTPS + 已安装 PWA 的 Chromium 系浏览器生效，其余环境静默降级；
- 与手动打开共用限制（单文件 ≤ 10MB 等）。

### 11. 系统分享目标

`share_target` 注册后，其他 App 分享文本 / MD 时可选「用 Markdown Preview 打开」。

**交互草案**

- 移动端系统分享面板出现本站入口；
- 分享的文本 / 文件进入站点后，转入本地文件会话或直接渲染预览。

**复用基建**

- `manifest.json`；
- `iris/js/local-docs.js` 的内存会话（刷新即清空，天然适合一次性分享内容）。

**实现要点**

- 最简方案：`method: "GET"` + query 参数承接分享文本（SW 不参与）；
- 接收文件（POST 到 Service Worker）方案复杂度高，建议二期；
- 进入后应立即渲染并把分享内容带入本地文件会话，避免用户困惑。

### 12. 扫码续读

> **状态：已实现 ✅** 悬浮球「扫码续读」生成当前文档 + 阅读位置的二维码（`?pos=N` 参数），扫码后自动定位；二维码沿用 qrcode 插件的外部服务方案。

桌面端生成当前文档 + 阅读位置的二维码，手机扫码接着看。qrcode 渲染器是现成的。

**交互草案**

- 悬浮球或分享工具条入口 → 弹窗展示二维码（URL 含文档路径与可选滚动位置参数），附当前阅读百分比；
- 手机打开后自动滚动到记录位置（配合「阅读位置续读」）。

**复用基建**

- qrcode 插件渲染器（`iris/plugins/qrcode.js`）；
- 悬浮球菜单与 i18n。

**实现要点**

- 阅读位置用 query 参数（如 `?pos=0.62`）而非 hash 附加，避免与文档路由冲突；
- 本地 / 局域网地址生成的二维码跨设备无效，需提示「需部署后的公网地址」。

## 五、写作流程

### 13. 草稿系统

frontmatter 写 `draft: true` 的文档不出现在目录树 / 搜索 / RSS，只在调试模式（`?debug=1`）可见，写作流程就完整了。

**交互草案**

- 三个构建脚本（file-tree / search-index / feed）解析 frontmatter 并过滤草稿；
- 运行时 GitHub API 回退路径同样过滤；
- `?debug=1` 打开时，草稿在侧边栏以「草稿」徽标显示，方便自查。

**复用基建**

- 构建脚本（`iris/scripts/build-*.js`）已解析文档元信息，增加字段成本低；
- `iris/js/markdown.js` 的 frontmatter 解析；
- `?debug=1` Debug Panel（已有，见 [开发者文档](../readme-dev.md)）。

**实现要点与边界**

- ⚠️ **内容仍是公开的静态文件**：草稿只是「不展示、不被索引」，任何知道 URL 的人仍可直接访问 `.md`。需要保密的内容请配合「文档密码保护（构建期加密）」；
- RSS 过滤在构建期完成，已生成的 `feed.xml` 需要重跑构建才会剔除。

### 14. 文档密码保护

frontmatter 写 `password: xxx`，WebCrypto 客户端解密，目标是在公开仓库里放私人笔记、零后端做到真加密。

**关键边界（必须先想清楚）**

当前管线中 `.md` 以明文静态文件被服务，**纯前端的「密码门」只是遮罩**——内容可以被直接 fetch。要做到真加密，必须构建期加密：由构建脚本把正文用 AES-GCM 加密写入产物（或以 ` ```encrypted ` 块替换正文），运行时用密码派生密钥（PBKDF2）解密后再走既有渲染管线。

**交互草案**

- 进入受保护文档显示密码输入卡片；
- 解密成功后按「路径 + 密码哈希」在 sessionStorage 记忆，站内跳转不重复输入；
- 密码错误时抖动提示，不暴露任何明文片段。

**复用基建**

- 构建脚本体系（可新增 `build-encrypt.js` 或在现有脚本内处理）；
- `markdown.js` 渲染管线（解密后的明文直接进管线）；
- WebCrypto 为浏览器原生能力，零依赖。

**实现要点**

- 密钥派生参数（迭代次数）在安全与移动端耗时间取舍；
- 解密结果按文档缓存，避免滚动 / 重新渲染时重复解密；
- 仓库里只存密文与盐，密码永不入库；密码丢失无法找回，需在文档中明示。
